LiteMonitor 1.3.7 发版审查结论
审查日期：2026-10-21

审查范围
对照 1.3.6 版本号提交 169e90a，审查后续本地提交、工作区修改及调用路径。
覆盖股票与汇率插件、内存格式化、分组别名、节假日回退、CPU 频率、GPU 映射与缓存、网页连接、HTTPS 证书验证及版本发布顺序。

审查发现与处理
1. 高优先级：更新检查、安装包下载和多个 HTTP 客户端无条件信任证书，无法验证服务器身份。
   已删除生产源码中的全部证书绕过回调，恢复系统默认校验。使用本地临时自签名证书分别验证插件直连、插件代理、更新检查、测速和原生行情客户端：修改前均接受不可信证书，修改后均拒绝。
2. CPU 备用频率读取提前返回标称值，可能使实际频率停止随负载变化。
   改为优先读取实际频率；缺失时用处理器标称频率结合性能百分比计算，再回退注册表基准。换算结果也进行有效范围、非数值和无穷值检查。
3. 失效或同名多卡旧配置在建图时回退自动模式，但刷新时仍被当成明确的单卡选择。
   现在依据实际匹配结果决定是否严格单卡刷新，保持建图和采集一致。
4. 低优先级显卡的风扇覆盖主显卡风扇。
   按已有硬件优先级保留首个有效映射；主卡缺失该传感器时仍允许补充。
5. 硬件重载后的建图包含 GPU 更新，却在硬件锁外执行。
   已将重载、建图和取值缓存预热放在同一临界区，避免与正常采集或关闭硬件并发。
6. 插件收到 HTML 或空正文时未实际解析 JSON，可能误判成功并缓存错误响应。
   现在实际解析 JSON，解析失败沿用步骤报错或显式备用步骤。HTTP 响应对象在读取结束后释放。
7. 用户取消与网络失败同时发生时，非取消异常可能覆盖已停用插件的原显示。
   可回退步骤捕获异常后再次检查取消，将用户取消作为取消异常传播，避免注入错误或备用结果。
8. NetworkStream.ReadTimeout 对异步读取无效，慢请求可能无限占用连接；不完整请求也可能进入 HTTP 处理。
   请求头增加五秒总截止时间与严格 8KB 上限，未完整接收则直接释放连接。
9. 网页密码未按浏览器编码方式解码，中文、空格、加号等密码无法认证，重复参数也有歧义。
   现在只解析请求目标中的独立密码参数，解码一次并拒绝重复参数。

修复前对照
新增硬件与网页回归初次运行：5 项通过、6 项失败，复现风扇覆盖、失效及同名显卡刷新不一致、特殊字符密码失败、不完整头部处理、异步读取无截止时间。
新增插件缓存回归复现 HTML 缓存及严格步骤错误接受网页响应；新增取消竞态回归也在修复前失败。
TLS 对照在修正本地测试证书的 Windows 私钥导入方式后，明确复现五条生产客户端路径接受不可信证书。
CPU 频率语义通过本机 Windows 计数器取样与代码审查确认；重载锁问题通过调用链审查确认，不将其描述为跨硬件并发压测结果。

验证边界与兼容性
硬件回归使用真实业务类和模拟硬件树，不安装驱动、不保存真实用户配置，不等于覆盖所有显卡、驱动、休眠恢复和多屏环境。
GPU 预热仅在开启 GPU 监控或网页服务时进行；多显卡上的初始化耗时仍需实机观察。
HTTPS 恢复系统验证后，无效证书、自签名证书或未被系统信任的代理证书会连接失败；已有备用数据源和镜像切换逻辑保留。
网页服务仍按原设计提供 HTTP，未在本次加入服务端 HTTPS 或改变部署方式。
本次审查未发现仍需阻止这些改动提交的已知问题，不代表完整程序不存在其他缺陷。
